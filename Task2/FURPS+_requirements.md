| Код    | Требования                                 | Комментарий  |
|--------|--------------------------------------------|--------------|
| F      | Функциональные (Functionality)             |              |
| F1     | Клиент может отправить заявку на депозитный счет через онлайн платформу.      |              |
| F1.1   | На платформе должен быть список доступных для клиента депозитных счетов      |              |
| F1.1.1 | Ставки на депозитных счетах должны быть актуальными.      |              |
| F1.2   | Новый клиент должен отправить заявку, указав ФИО и номер телефона.       |              |
| F1.2.1 | Cотрудник банка должен получить заявку в CRM и иформацию о персональных предложениях для подтверждающего звонка клиенту.       |              |
| F1.2.2 |  Сотрудник банка должен иметь возможность просмотреть данные о заявке, а также иметь доступ к персональным предложениям для нового клиента.       |              |
| F1.2.3 | Новый клиент должен придти в отделение банка для подтверждения личности.       |              |
| F1.3   | Клиент должен иметь возможность открыть дополнительный счет без визита в банк.       |              |
| F1.3.1 | Клиенту доступна информация о персональных предложениях.       |              |
| F1.3.2 | Клиент может указать счет и сумму депозита.       |              |
| F1.3.3 | Клиент должен подтвердить открытие нового счета по коду из СМС       |В MVP подтверждение присылает сотрудник бэк офиса|
| F1.4   | Клиент должен получить уведомление об открытии счета по СМС       |В MVP Уведомление присылает сотрудник бэк офиса|
| U      | Удобство использования (Usability)          |              |
| U1     | Интерфейс должен быть удобным и должен использовать дизайн систему, принятую в компании|              |
| R      | Надёжность (Reliability)           |              |
| R1     | Availability - 99.9%               |              |
| R2     | Режим работы 24/7                  |              |
| R3     | В случае сбоев траффик переключается на резервный ЦОД  |              |
| P      | Производительность (Performance)   |              |
| P1     | Время ответа не более 500 мс       |              |
| P2     | Возможность горизонтального масштабирования, за исключением баз данных   |              |
| P3     | Должно быть вертикальное масштабирование БД при увеличении количества клиентов   |              |
| S      | Поддерживаемость (Supportability)  |              |
| S1     | Поддержка интеграционного тестирования  |              |
| S2     | Использовать Blue/Green при переходе на новую версию  |              |
| +R     | + Ограничения (Restrictions)       |              |
| +R1    | Асинхронное обращение к АБС через Kafka     |   БД АБС уже перегружена           |
| +R2    | Новая функиональность должна быть выполнена в виде микросервисов  |              |
| +R3    | Для БД используются Oracle и MS SQL   |              |
| +R4.   | На верхнем уровне используется поюзерное (UserID) шардирование, для того чтобы использовать несколько БД и масштабировать сервисы относительно БД  | При возрастании количества пользователей можно добавлять новые кластеры с БД и перераспределить пользователей межжду кластерами  |
