| F1       | Клиент может подать заявку на открытие депозита онлайн.                                                                                                              |                                                                                                                                                              |
| F1.1     | На сайте и в интернет-банке отображается список доступных депозитов с актуальными ставками.                                                                          | Ставки должны обновляться ежедневно. | F1.1.1   | В интернет-банке авторизованному клиенту дополнительно отображаются персонализированные ставки.                                                                      | Персональные ставки рассчитываются на основе данных клиента в АБС.                                                                                          |

| F1.2.2   | Оператор кол-центра получает заявку в системе кол-центра и может просмотреть доступные ставки для звонка клиенту.                                                    | Используется система кол-центра (не отдельная CRM).                                                                                                         |
| F1.2.3   | Новый клиент обязан посетить отделение банка для идентификации личности.                                                                                             | Регуляторное требование: банк не может принять нового клиента без очной проверки документов (AML/KYC).                                                       |

| F1.3.1   | Авторизованный клиент выбирает тип депозита, указывает счёт списания и сумму.                                                                                        |                                                                                                                                                              |
| F1.3.2   | Клиент подтверждает заявку одноразовым кодом из СМС.                                                                                                                 | Функционал СМС-кода реализуется командой банка без изменений в ядре системы подрядчика.                                                                      |

| F1.4.2   | После подтверждения ставки АБС автоматически отправляет клиенту СМС-уведомление с указанием ставки.                                                                  | СМС отправляется через СМС-шлюз, а не вручную сотрудником.                                                                                                  |
| F1.4.3   | После открытия депозита АБС автоматически отправляет клиенту СМС-уведомление об открытии счёта.                                                                      |                                                                                                                                                              |
| F1.5     | **Управление ставками депозитов в АБС.**                                                                                                                             |                                                                                                                                                              |
| F1.5.1   | Сотрудники бэк-офиса депозитов могут просматривать и обновлять ставки в АБС.                                                                                         | Заменяет текущий процесс с Excel-файлами.                                                                                                                   |
| F1.5.2   | Сотрудники бэк-офиса кредитов имеют доступ к ставкам в рамках своих полномочий.                                                                                      | Разграничение доступа: сотрудники депозитов и кредитов не видят данные друг друга за пределами ставок — требование безопасности.                              |

| U1       | Интерфейс должен соответствовать дизайн-системе, принятой в компании: фирменные цвета, брендированные элементы.                                                      |                                                                                                                                                              |
| U2       | Все пользовательские операции должны отвечать в пределах миллисекунд — интерфейс не должен ощущаться медленным.                                                       | Текущая проблема: некоторые справочные данные в интернет-банке загружаются более 1 секунды — необходимо устранить.                                            |
| **R**    | **Надёжность (Reliability)**                                                                                                                                         |                                                                                                                                                              |
| R1       | Доступность сервисов — 99.9%.                                                                                                                                        |                                                                                                                                                              |
| R2       | Режим работы — 24/7.                                                                                                                                                 |                                                                                                                                                              |
| R3       | При сбое основного ЦОД трафик автоматически переключается на резервный ЦОД.                                                                                          | У банка есть резервный ЦОД. Необходимо обеспечить replikацию данных и готовность резерва к приёму нагрузки.                                                  |
| **P**    | **Производительность (Performance)**                                                                                                                                 |                                                                                                                                                              |
| P1       | Время ответа на пользовательские операции в интернет-банке и на сайте — не более 200 мс.                                                                             | Фоновые операции (асинхронная обработка заявки в АБС) допускают более длительное время выполнения.                                                           |
| P2       | Сервисы интернет-банка должны поддерживать горизонтальное масштабирование с равномерным распределением нагрузки между серверами и ЦОД.                               |                                                                                                                                                              |
| P3       | База данных должна поддерживать горизонтальное масштабирование при росте числа пользователей.                                                                        | Конкретный механизм (шардирование, партиционирование и т.д.) определяется на этапе проектирования архитектуры.                                               |
| **S**    | **Поддерживаемость (Supportability)**                                                                                                                                |                                                                                                                                                              |
| S1       | Поддержка интеграционного тестирования для всех новых сервисов.                                                                                                      |                                                                                                                                                              |
| S2       | Применять Blue/Green deployment при выпуске новых версий сервисов.                                                                                                   |                                                                                                                                                              |
| S3       | Разработать документацию для новых сервисов, достаточную для их дальнейшего расширения другими командами.                                                             |                                                                                                                                                              |
| **+R**   | **Ограничения (Restrictions / Design Constraints)**                                                                                                                  |                                                                                                                                                              |

Прямая интеграция с БД — текущее узкое место. Kafka выбрана как перспективное решение для очередей сообщений.                            |
| +R2      | Новая функциональность реализуется в виде микросервисов.                                                                                                             | Текущий интернет-банк — монолит. Новые сервисы (в рамках депозитного направления) разрабатываются отдельно, без изменений в ядре системы подрядчика.          |
| +R3      | В качестве СУБД использовать Oracle и MS SQL как основные платформы.                                                                                                 | Новые технологии допускаются при условии совместимости с существующими платформами и наличия внутренней экспертизы.                                            |
| +R4      | АБС поддерживает только вертикальное масштабирование из-за архитектуры Oracle-базы.                                                                                  | Архитектурное ограничение, которое необходимо учитывать: снижение нагрузки на АБС достигается через асинхронное взаимодействие (+R1), а не масштабированием.  |
| +R5      | Весь трафик между клиентом и сайтом, а также между клиентом и интернет-банком должен шифроваться по протоколу TLS.                                                   | Через эти каналы передаются персональные и финансовые данные клиентов.                                                                                       |
| +R6      | Функционал SMS OTP в интернет-банке должен быть реализован командой разработки банка без модификации ядра системы подрядчика.                                         | Изменения в ядре подрядчика требуют привлечения внешней команды и увеличивают сроки и стоимость.                                                             |
| +R7      | Доступ сотрудников бэк-офиса депозитов и кредитов к данным друг друга должен быть разграничён на уровне системы.                                                     | Требование информационной безопасности. Сотрудники кредитного блока передают данные о риске через контролируемый канал, а не через прямой доступ к данным.    |
