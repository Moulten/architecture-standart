### <a name="_qmphm5d6rvi3"></a>**Решение**

Диаграммы C4 (контекст и контейнеры) приведены в директории `Schemas/`.

**Ключевые архитектурные решения:**

- **Новый Deposit Application Service** реализуется как отдельный микросервис командой банка — без изменений в ядре платформы подрядчика. Сервис публикует события заявок в Kafka.
- **Kafka** используется как асинхронная шина между интернет-банком и АБС, что позволяет избежать прямой нагрузки на Oracle и масштабировать интернет-банк независимо.
- **Модуль ставок в АБС** заменяет процесс с Excel-файлами. Ставки доступны для бэк-офиса депозитов и кредитов с разграничением прав.
- **SMS OTP** реализуется командой банка поверх существующего SMS-шлюза, без изменений в ядре системы подрядчика.
- **MVP**: бэк-офис вручную обрабатывает заявки в АБС. Полная автоматизация — цель на год.
### <a name="_bjrr7veeh80c"></a>**Альтернативы**

| Альтернатива | Причина отказа |
| :- | :- |
| Прямой синхронный вызов CBS API из интернет-банка | АБС не имеет готового API; прямая интеграция с БД перегружает Oracle. Нарушает NFR4. |
| Добавить логику депозитов в монолит интернет-банка без нового сервиса | Монолит несовместим с Kafka; изменения в ядре требуют подрядчика и увеличивают сроки. |
| RabbitMQ вместо Kafka | Kafka выбрана как перспективное решение для банка. RabbitMQ создаст лишнюю технологию. |

---

**Недостатки, ограничения, риски**

| # | Описание |
| :-: | :- |
| 1 | **Kafka — новая технология для команды интернет-банка.** Требует обучения и времени на освоение. |
| 2 | **Асинхронный процесс в MVP.** Клиент не получает мгновенного результата — нужно выстроить UX с ожиданием. |
| 3 | **АБС масштабируется только вертикально.** При росте объёма заявок узким местом останется Oracle. Kafka частично снижает нагрузку за счёт буферизации. |
